## 探针覆盖与结论边界

- fopen/open 只观察目标资源和选定目录中的读打开，并非全进程所有文件打开总数。O_WRONLY 被排除，fopen 的 w+/a+ 等模式也不在当前读打开统计范围内。
- 宿主通道覆盖部分 C 路径/fd 入口和 Foundation selector。自检仅验证宿主测试调用可见，不证明厂商组件、类簇子类、系统库内部或窗口外的调用全部可见。
- Foundation 外层拦截执行期间会抑制下层计数，因此 C 入口零命中不能单独证明没有内容读取。
- stat/access 表示路径探测，不等于读取内容。opendir 当前只统计成功调用，其零计数不能排除失败尝试、fdopendir、预先创建的目录句柄或系统库内部枚举。
- 相同的目录类别合计和无扩展名合计是两个边缘分布，不能证明每次用户目录访问都指向无扩展名目录。“无扩展名”也不等于“目录”。
- 目录外报告出现 `.mwua` 仅证明观察到了该 basename；没有逐事件通道、目录类别或调用栈，不能确定它的读写角色、来源或生成方式。明文字符串搜索未命中不证明必须运行时拼接。
- capture 全程暂停当前线程跟踪，排除了扫描在本线程通过已覆盖入口产生的计数。其它线程活动和未覆盖途径仍需独立判断。
- 原始字节码按 ARM 指令模式搜索不到 svc，不足以证明虚拟机不会通过宿主函数或解释器执行系统调用；这不是完整控制流证明。

## 本轮探针修正

1. fd 每次观察用 F_GETPATH 查询当前路径，再统一分类一次；移除重复 calls++。
2. 移除固定 24 槽的路径缓存和仅用于缓存淘汰的 close 拦截，避免容量漏报、dup2 身份替换与其它关闭途径导致的旧路径误判。
3. 无法反查路径仍计入一次调用与“其它”，不丢弃观察。路径查询与事件发生之间仍可能有其它线程修改描述符，不宣称取得原子身份快照。
4. 每通道 `calls == target + scoped + outside` 改为精确断言；场景中 Foundation 命中数仍可使用下限。
5. 新增 32 个描述符、同 fd 的 dup2 身份替换、管道无路径且保留 errno 的原生回归场景。平台 fd 自检未命中时不宣称这些行为得到验证。

匿名标签仍使用进程随机 salt。输入是沙盒相对路径，不包含不可猜的容器 UUID，因此不能以 UUID 为由改成公开常量 salt。确有跨进程关联需求时，可另行设计本机持久随机 salt 和生命周期，再单独验证；本轮没有改动标签机制。
