# iOS 校园洗衣体积精简

## 当前包及验收状态

用户要求接近安卓的组件化精简，不满足于删除原校园素材。本轮没有把整个校园主程序误称为独立 SDK；已完成资源清理、符号精简的实际试验，并把后续课表整合构建改为 Release。完整的静态业务代码拆分尚未完成。

| 包 | IPA 大小（十进制 MB） | 解包文件总量（十进制 MB） | 状态 |
|---|---:|---:|---|
| 已验证 v5 整合版 | 201.5 | 595.1 | 用户确认通过 |
| v6 资源精简 | 175.0 | 563.0 | 文件与加载依赖核对通过 |
| v7 资源与符号精简 | 131.7 | 338.6 | 运行数据离线核对通过，尚待真机 |

v7 是对已验证 v5 库的二进制精简试验，尚不包含随后提交的“未支付微信返回结束本地付款”改动。下一次 Release 构建包含该改动，下载后再按相同流程生成新精简包；不能把当前 v7 当成所有最新修改的构建产物。

## 已采取的措施

1. `slim_campus_timetable_host.py` 删除明确的校园无关素材和扩展，保留全部真实加载依赖及未知资源。
2. `compact_campus_timetable_host.py` 使用 LLVM `--discard-all` 剥离调试和本地符号，输出独立文件；不使用默认 `strip-all`。原主程序从 364,672,080 字节变为约 189,360,512 字节，整合库从 122,750,312 字节变为 73,659,528 字节。
3. 剥离前后核对非 LINKEDIT 运行段、全部 section 元数据与内容、入口及其它加载命令、dyld 绑定/重定位/导出数据、外部符号和间接符号身份。原主程序 109,534 个外部符号及整合库 1,566 个外部符号均保留。代码与 Objective-C 运行数据不按名字猜测删除。
4. 更新整合库摘要并记录源包/新映像摘要，再核对每个保留文件及整个依赖闭包。保留原包，输出必须使用新名称；需要递归重签。
5. `build_campus_timetable_host.sh` 默认构建 Kotlin Release framework，启用 `smallBinary`，使用 Objective-C `-Os`、Swift `-O`，链接后剥离本地/调试符号并复核导出白名单。`CAMPUS_HOST_BUILD_TYPE=debug` 保留调试构建选项。Release 的实际减小幅度需要新产物测量，不预设体积。

LLVM 选项依据：[llvm-strip 官方文档](https://llvm.org/docs/CommandGuide/llvm-strip.html)。Kotlin 体积选项依据：[Kotlin/Native binary options](https://kotlinlang.org/docs/native-binary-options.html)。本地试验使用官方 Rust 分发中的 LLVM 工具，下载摘要与官方分发清单一致；工具放在本地分析生成目录，不提交仓库。

## 与安卓组件化精简的差距

原主程序包含约 120 MB 原生机器码、16,605 个 Objective-C 类及多组全局初始化入口；SecurityGuard、MTOP 和设备组件静态混在其中。名字中包含 SecurityGuard/SGMain/SGMiddleTier/SGSecurityBody/UMID/UTDID 的 56 个类只是候选入口，不是完整依赖集合。底层 C/C++、虚拟化程序、宿主桥、常量和全局状态仍有其它依赖。

主程序直接加载广告等 Framework；在保持加载命令和绑定表的条件下直接删除这些库会缺失真实依赖。要移除其代码，必须继续完成主程序级的依赖迁移或重建，处理 Objective-C 类/分类注册、构造器、直接与间接调用、全局数据、重定位和 SDK 自身检查。当前没有来源明确、可独立链接且已验证的校园 6.8 发行库，也没有已完成的二进制拆分工具。因此不能承诺已经能得到只有几十 MB 的独立 SDK 版。

本轮检查不能替代真机：至少验证启动、校园会话恢复、扫码/程序报价、本人确认下单、微信跳转返回、付款状态和订单查询。v7 先作为体积优化对照，不覆盖用户已验证版本。
